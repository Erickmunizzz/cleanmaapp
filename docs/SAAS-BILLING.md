# CleanMa SaaS billing and client payment separation

**CleanMa plans** use the platform's own Stripe Billing, not Stripe Connect. Owner-only Checkout at `/planos` uses the six active GBP prices in the server catalog: Starter £89.99/month or £928.70/year, Growth £179.99/month or £1,857.50/year, and Scale £299.99/month or £3,095.90/year. The app verifies the provider's price, currency, amount, frequency and account before opening Checkout. It does not send a connected-account header or collect a 1% Connect fee on these plans. If the workspace already has an active/past-due paid subscription, it opens the configured Customer Portal instead of starting a second subscription.

The code sets GBP and uses Stripe's dynamic payment methods. The live platform default examined for this release enables card and Apple Pay; Apple Pay is shown only for eligible customers/devices. Google Pay, Pix and Boleto were not enabled/eligible in that platform default. This is distinct from the Connect configuration. See [Stripe Payment methods](https://dashboard.stripe.com/settings/payment_methods) and [dynamic payment methods](https://docs.stripe.com/payments/payment-methods/dynamic-payment-methods). Review UK tax/invoice requirements before changing Checkout or enabling [Stripe Tax](https://docs.stripe.com/billing/taxes/collect-taxes) for production.

## Configuration and verification

In the existing **app** Vercel Production project (not the landing):
- `STRIPE_SECRET_KEY`: live account's server-only key. `STRIPE_PLATFORM_ACCOUNT_ID`: optional explicit account ID, otherwise CleanMa's pinned platform ID is used.
- `STRIPE_WEBHOOK_SECRET`: signing secret for the live platform destination `https://cleanmaapp.com/api/stripe-webhook`; do not substitute the signing secret of another watcher, Connect destination or sandbox.
- `STRIPE_BILLING_PORTAL_CONFIG`: active live configuration. Verify invoice history, updating the payment method, and cancellation at period end. Only expose CleanMa catalog prices if enabling plan changes.
- In [Stripe Workbench → Webhooks](https://dashboard.stripe.com/workbench/webhooks), ensure the platform destination includes `checkout.session.completed`, `checkout.session.async_payment_succeeded` / `async_payment_failed` (for eligible asynchronous methods), `customer.subscription.created` / `updated` / `deleted`, and `invoice.paid` / `invoice.payment_failed`. If Stripe-side pause/resume is used, add `customer.subscription.paused` and `customer.subscription.resumed` (not required for normal cancellation). The current portal does not offer pause. Do not repoint this endpoint to Connected Accounts events.

The signed webhook reads exactly one supported subscription item and its latest invoice from Stripe. An incomplete Checkout or unsuccessful first payment does not end an unexpired local trial. A paid invoice activates or renews access, renewal failure takes it to past due, later payment restores it, scheduled cancellation retains the current paid period, and final cancellation removes operational access without deleting workspace data. A returned browser or a connected merchant's customer event cannot confirm a CleanMa SaaS payment. Keep the SQL migration `20261126165200_saas_billing_checkout_lifecycle.sql` ahead of the code deploy for existing installations.

Run a **Stripe sandbox** acceptance check: end of local trial, successful initial Checkout, failed and recovered renewal, cancellation scheduled and ended, fresh resubscription, and replay of the old canceled event. Use an isolated Supabase project and sandbox Stripe endpoint/key/catalog for these tests rather than modifying live prices or accepting a test secret in production. Verify whether each expected event has a 2xx delivery in Workbench and inspect the corresponding workspace access. A sandbox is not proof of a live payout.

## Stripe Connect: separate client payments and the platform's 1%

- Set the live Connect app's `STRIPE_CLIENT_ID` in the **app** Vercel Production environment, for the same platform as `STRIPE_SECRET_KEY`. Keep the OAuth redirect allowlisted at [Stripe Connect OAuth settings](https://dashboard.stripe.com/settings/connect/onboarding-options/oauth): `https://cleanmaapp.com/api/stripe/connect/callback` (exact HTTPS host/path).
- Go to **Finance → Payments → Payment & Accounting Connections** from `cleanmaapp.com`, and authorize the company's own independent Stripe account. Use the same browser and finish within 10 minutes; if verification takes longer, complete that in Stripe first and restart. Stripe's `read_write` flow cannot authorize accounts controlled by another platform, and CleanMa cannot authorize its own platform as the merchant. Use **Check status** and confirm active card capability on the merchant. [Stripe Connect OAuth reference](https://docs.stripe.com/connect/oauth-reference)
- The configured flow takes 1% as an application fee on direct merchant payments/paid subscription invoices. Check [Collected fees](https://dashboard.stripe.com/connect/application_fees) and [Payout settings](https://dashboard.stripe.com/settings/payouts) on the **platform** account. In Brazil, the bank must be an eligible Brazilian BRL checking account held under the same CPF/CNPJ as the Stripe account. Keep identity and bank verification current. [Stripe's Brazilian bank requirements](https://support.stripe.com/questions/supported-bank-accounts-in-brazil?locale=pt-BR)
- Stripe's ordinary self-serve cross-border transfers/payouts do not list Brazil. That is a different flow from a UK merchant taking a direct GBP charge and the Brazilian platform receiving an application fee. Ask Stripe to confirm that exact account pairing, both one-off and recurring application fees, conversion/settlement of the fee and payout to your BRL bank. Do not assume it is enabled based on OAuth, sandbox or the platform's Canadian/US/UK transfer documentation. [Direct charges](https://docs.stripe.com/connect/direct-charges?platform=web&ui=stripe-hosted) · [Cross-border payouts](https://docs.stripe.com/connect/connect-cross-border-payouts)
